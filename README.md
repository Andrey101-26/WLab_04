# ЛР4. Алгоритмический мини-пакет

Вариант для номера 13 при отдельном отсчёте в каждом списке: НОД, пузырьковая сортировка, сортировка слиянием и стек. Python 3.10+.

## Запуск

В PowerShell из корня проекта. Команды используют Python из папки .venv напрямую. Для настройки окружения используется uv. Если .venv ещё нет, сначала выполните uv venv.

```powershell
uv pip install --python .venv/Scripts/python.exe -e ".[test]"
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m algorithm.benchmark --output benchmark.csv
```

В Git Bash можно активировать окружение один раз, а затем использовать команду python:

```bash
source .venv/Scripts/activate
python -m pytest
python -m algorithm.benchmark --output benchmark.csv
```

## Устройство

- `gcd.py` — НОД с циклом и рекурсией. Отрицательные аргументы заменяются модулями. Нецелые аргументы вызывают `TypeError`, два нуля — `ValueError`.
- `sorting.py` — сортировки целых чисел. Обе возвращают новый список, исходный сохраняется. Аргумент другого типа или элемент, отличный от `int` (включая `bool`), вызывает `TypeError`.
- `stack.py` — `push` кладёт элемент наверх, `peek` показывает верхушку, `pop` снимает её. Поддерживаются `len` и `bool`. На пустом стеке `peek` и `pop` вызывают `IndexError`.
- `datasets.py` — случайные, отсортированные, обратные, почти отсортированные списки и списки с дубликатами. Локальный `Random(seed)` позволяет повторить случайные наборы.
- `benchmark.py` — генераторы готовят вход, обе сортировки получают свежую копию, времена записываются в CSV. Генерация и копирование входа происходят до таймера. Замер включает сам вызов сортировки вместе с её внутренними проверками и выделением памяти.

## Сложность

| Алгоритм | Время | Дополнительная память |
|---|---|---|
| НОД с циклом | O(log m) шагов для двух ненулевых аргументов, где m — меньший модуль | O(1) переменных |
| НОД с рекурсией | O(log m) шагов при тех же условиях | O(log m) кадров вызова |
| Пузырьковая | O(n) на отсортированном списке, O(n²) в худшем случае | O(n) на копию |
| Слиянием | O(n log n) | O(n) для списков и O(log n) для стека вызовов |
| Стек | Добавление и извлечение амортизированно O(1), просмотр, размер и проверка пустоты O(1) | O(n) на хранение n элементов |

Для НОД указано число шагов. Стоимость операций над очень большими целыми дополнительно зависит от их разрядности. Глубина рекурсии Python ограничена. Текущее значение показывает `sys.getrecursionlimit()`. При превышении возникает `RecursionError`; итеративная версия не расходует стек на каждый шаг.

## Замеры

Размеры 100, 1000 и 10000, пять типов входа, пять повторов, seed 42. `benchmark.csv` содержит каждый замер и медиану в миллисекундах.

На обратном списке медиана пузырьковой сортировки выросла с 128 мс (1000 элементов) до 11 162 мс (10 000), примерно в 87 раз при десятикратном росте входа. Это согласуется с квадратичным числом сравнений. Слияние на том же входе выросло с 3,37 до 40,41 мс, примерно в 12 раз, что согласуется с O(n log n).

На уже отсортированном списке из 10 000 элементов пузырьковая сортировка заняла 1,32 мс, слияние — 25,36 мс. Пузырьковая версия остановилась после первого прохода без обменов, а слияние всё равно делило и объединяло половины.
